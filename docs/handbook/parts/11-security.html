11. Security, privacy and compliance

Note. This section lists the technical measures and the topics that need legal review. It is not legal advice; the company’s counsel should confirm each legal point for Germany and the EU.

11.1 Security measures

AreaMeasure
TransportTLS everywhere (HSTS on the web). No plain HTTP endpoints.
AuthenticationArgon2id password hashes; hashed one-time codes with expiry and attempt limits; refresh token rotation with reuse detection; per-device sessions; staff accounts require two-step verification.
AuthorizationEvery endpoint checks role, approval and ownership on the server. Automated tests for access to other users’ bookings, tickets, messages and admin endpoints (IDOR).
InputSchema validation on every request; parameterised queries (ORM); size limits; file type checks on uploads; no user HTML.
PaymentsCard entry only through Stripe’s UI (keeps PCI DSS scope minimal); webhook signatures verified; idempotency keys; no card data in logs.
TicketsTicket codes are random and unguessable (or signed); every scan is validated on the server and logged. DECISION Offline scanning (blueprint F22).
SecretsStored in the cloud secrets manager and CI secrets; never in the repository or in EXPO_PUBLIC_ variables; rotated on staff changes.
AbuseRate limits on sign-in, codes, messages, friend requests, reports and search; spam and bot detection on registration.
DataEncryption at rest for the database, backups and storage; least-privilege access; production data never copied to development.
Supply chainDependabot (or similar) for app and API dependencies; lockfiles committed; CI fails on known critical vulnerabilities.
AuditAppend-only audit log for staff decisions and money movements.

11.2 Privacy (GDPR)

  • Hosting and processors: personal data stays in the EU; list every processor (cloud, Stripe, email, SMS, maps, Sentry, analytics, Expo, Apple, Google) in the records of processing with a DPA.
  • User rights in the app: data export and account deletion already exist in Account & security; the backend must implement them (export as a downloadable file; deletion with removal of profile, posts, comments, photos, friends and messages).
  • Retention (as stated in the app’s privacy summary): profile and social content until account deletion; booking, payment, refund, payout and ticket records for the period German tax and commercial law requires, also after deletion; support cases and moderation decisions under a retention policy so decisions stay traceable.
  • Location: used only while the user uses Nearby or the map, and only with permission. Do not store precise location history.
  • Photos: strip location metadata on upload.
  • Consent: analytics and any non-essential cookies or device storage need prior consent (web banner, in-app setting).
  • Children and age: DECISION Minimum age for accounts. Events can carry an age limit (for example 18+); the door team checks ID.

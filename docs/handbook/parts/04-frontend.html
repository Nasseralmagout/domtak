4. Front-end architecture (Android, iOS, Web)

One TypeScript codebase in mobile/ produces all three apps. Android and iOS are native apps built with Expo (React Native); the web app is the same code rendered by React Native Web and exported as a static single-page app.

4.3 How data flows today

  • Sample data (src/data/mock.ts): profiles, venues, events, posts, stories, bookings b1–b7, requests r1–r6, lessons, communities, support case DT-4821, admin applications.
  • Store (src/store/useApp.ts): one zustand store persisted to AsyncStorage (web: localStorage) under the key domtak-app. About 90 actions implement every user action (section 7 maps them to endpoints). Selectors must return stable values (zustand v5).
  • Rules (src/lib/*): pure functions for labels, state transitions, prices, deadlines, readiness and permissions. Keep them for display on the client, and re-implement the authoritative versions on the server.
  • Demo clock: TODAY = 2026-10-14T12:00 in src/lib/format.ts keeps the sample data current. Replace it with the real time in production.

4.6 From demo to production: integration plan

  1. API client. Add a typed API client (generated from the backend’s OpenAPI document) and a server-state library such as TanStack Query for caching, retries and pagination. Base URL from EXPO_PUBLIC_API_URL.
  2. Reads. Replace imports from src/data/mock.ts with queries, one domain at a time (profiles, venues, events, posts, bookings…). Keep the src/data/types.ts shapes as the contract; the backend returns the same field names (camelCase JSON).
  3. Writes. Replace each zustand action with a mutation that calls the matching endpoint (section 7). The server returns the new state; the client never computes a payment or booking state on its own.
  4. Auth. Store the refresh token in expo-secure-store on mobile and in an httpOnly cookie on the web; keep the short-lived access token in memory. Refresh on 401. Respect “remember me”.
  5. Images. Replace ImgKey image keys with URLs from the media service (CDN). Keep bundled assets only for brand art (logo, onboarding illustrations).
  6. Remove demo pieces (appendix B): demo controls (DemoBar) on 10 screens, the admin demo switch, sample scanner codes, the fixed TODAY date and sample application shortcuts.
  7. Real-time and push. Subscribe to the message and notification channels (section 5.6); register the push token after sign-in.
  8. States. Every screen gets loading, empty, error and offline states for real network conditions. Mutations that move money use idempotency keys.
  9. Persistence. Persist only the session, preferences and drafts locally. Clear user data on sign-out.

4.8 Working on the app

cd mobile
npm ci                     # install exact versions from package-lock.json
npx expo start             # dev server: press a (Android), i (iOS simulator), w (web)
npm run typecheck          # tsc --noEmit
npm run lint               # ESLint (strict rules: no setState in effect bodies, no Date.now in render)
npm run icons              # regenerate web icon paths after using a new icon name
npm run build:web          # static web build into mobile/dist
npx expo-doctor            # dependency and config check

Run typecheck and lint before every pull request. Never create or edit android/ or ios/ by hand; change app.json or a config plugin instead.

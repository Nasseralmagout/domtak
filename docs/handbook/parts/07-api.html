7. API specification (REST v1)

7.1 Conventions

TopicRule
Base URLhttps://api.<domain>/v1. JSON in and out, camelCase field names matching mobile/src/data/types.ts.
AuthenticationMobile: Authorization: Bearer <access token>. Web: httpOnly session cookie plus a CSRF token header on writes.
MoneyInteger euro cents in every money field (amount, price, total…), with currency: "EUR" on payment objects.
TimeISO 8601 in UTC (2026-10-24T18:00:00Z); dates as YYYY-MM-DD.
ListsCursor pagination: ?limit=20&cursor=… → { items: [...], nextCursor }.
ErrorsRFC 7807 problem JSON: { type, title, status, detail, code, fields }. Stable codes the app can map to text, for example ROLE_NOT_APPROVED, BOOKING_STATE_CONFLICT, QUOTE_EXPIRED, DEADLINE_PASSED, TICKET_ALREADY_USED, WRONG_EVENT, PAYMENT_DECLINED.
State changesActions are explicit endpoints (POST /bookings/:id/cancel), not free PATCHes of status. Each returns the updated resource. Concurrent changes return 409.
IdempotencyIdempotency-Key header is required on every request that creates a booking, order, payment, refund or payout. Repeating the key returns the first result.
Rate limits429 with Retry-After. Strict limits on auth, codes, search and reports.
ContractOpenAPI 3.1 document at /v1/openapi.json; the app’s API client is generated from it in CI.

The third column names the store action in mobile/src/store/useApp.ts (or other store file) that the endpoint replaces.

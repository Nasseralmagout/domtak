About this document

Domtak V1 exists today as a complete, working front-end: one Expo / React Native codebase that runs as an Android app, an iOS app and a web app. Every screen and flow works, but on sample data stored on the device. There is no server yet, and payments, messages and notifications are simulated. This handbook describes what is built, what the backend must provide, which external services must be activated, and how to ship all three platforms.

How to read the labels

Recommendations for technologies and vendors are marked as such. They are sensible defaults that fit the existing code and EU/GDPR hosting; the teams may change them, provided the contracts in this document (data model, API behaviour, state machines and acceptance criteria) are kept.

1. Project overview

1.1 Product summary

Domtak is a music-first platform for Berlin that connects fans, musicians (solo artists, bands and DJs), venues and event organizers. It combines four products in one app:

  • Social: an Instagram-style home feed (For You, Following, Nearby), stories, live, comments, follows, friends, direct messages and platform-run music communities.
  • Events and tickets: discovery by category, filters and a nearby-events map, event pages and discussions, ticket checkout, an e-ticket wallet with QR codes, and door check-in.
  • Booking: booking musicians, venues and music lessons, at a listed price or by itemised quote, with a 24-hour provider response window, a payment state for every booking, change requests, cancellations, disputes and reviews.
  • Professional workspaces: reviewed applications for artists, venues and organizers; requests, availability, services and pricing, earnings and payouts, event management, promotion, guest lists and a QR scanner; plus an admin console for applications, booking exceptions, finance and moderation.

1.3 Scope of work for the teams

Backend team
  • API and database for every entity in section 6
  • Authentication, roles, applications and staff access
  • Booking, quote and payment state machines with timers
  • Payment provider integration, webhooks, refunds, payouts
  • Tickets, QR validation and check-in
  • Feed, comments, messages (realtime), notifications
  • Media storage, search, geo queries
  • Admin, moderation, support cases, audit log
  • Hosting, monitoring, backups, GDPR tooling
Frontend team
  • API client layer; replace mock data and local actions
  • Secure token storage and session handling
  • Native modules: push, location, maps, image picker, payments
  • Remove demo controls; real dates and real admin access
  • Error, loading and offline states against a real network
  • Replace watermarked sample photos and the map image
  • Store builds, signing, submission, over-the-air updates
  • Web hosting and domain
  • Automated tests for the acceptance criteria (section 12)
